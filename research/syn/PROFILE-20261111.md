# SyN profiling: current CUDA baseline

## Outcome

The qualified planar workload is about **31% slower than FireANTs** locally.
Six small prototype families were evaluated; **none was promoted**. Production fitting,
precision, iteration budgets and safety checks remain unchanged.

## Matched baseline

Dagobah, AC power, RTX 5080 Laptop GPU, eight CPU threads, both TF32 flags off.
Current eager benchmark inputs/settings: 100 updates, no early stopping, identical
source hashes, complete API calls including native CPU output. Five timing calls
include the first; memory and full-grid accuracy use separate processes.
FireANTs reports fused ops unavailable and its fused interpolator disabled.

| Workload/backend | Median seconds | Worst truth RMS, voxels | Qualification |
| --- | ---: | ---: | --- |
| 100 planar frames, voxreg CUDA, batch 32 | 1.8666 | 0.265150 | Pass |
| 100 planar frames, FireANTs CUDA, batch 32 | 1.4203 | 0.299721 | Pass |
| Volume pair, voxreg CUDA | 1.4356 | 0.306431 | **Fails 0.30 gate** |
| Volume pair, FireANTs CUDA | 1.5058 | 0.358709 | **Fails 0.30 gate** |
| Volume pair, voxreg CPU | 32.2661 | 0.306434 | **Fails 0.30 gate** |

Do not use the failing volume cases to claim qualified speedups. The CPU follow-up
hit a 300-second outer supervisor timeout. Its orphan FireANTs worker was stopped;
one completed first-call sample remains, but no completed CPU comparison is claimed.
A separate interruption record preserves this fact without rewriting raw results.

## Profile attribution

One **warmed, instrumented full call** per backend retained the original workload
and 100-update budget. These are diagnostics, not additional throughput samples.
Inclusive host spans overlap; do not add them or equate them to kernel-active time.
Instrumentation changed wall times, so compare the uninstrumented baseline above.

| voxreg span | Calls | Inclusive host milliseconds |
| --- | ---: | ---: |
| Candidate updates | 400 | 833 |
| Field smoothing, within updates | 1600 | 281 |
| Sampled Jacobians, including final checks | 812 | 176 |
| Final halfway inversions | 8 | 274 |
| Midpoint objectives | 408 | 364 |

The profiles show substantial launch/dispatch and field-operation work, rather
than just image loading or NCC forward evaluation. FireANTs uses different
optimizer/field/finalization machinery; not all work is interchangeable. Removing
voxreg's sampled Jacobian guards, double finalization or inverse diagnostics is
not an acceptable way to close the gap.

## Rejected prototypes

Each row has five alternating baseline/candidate complete calls after explicit
warm-up, with all samples retained. Rows are separate experiments, not pooled
measurements. Accuracy checks follow timing, outside its boundary.

| Candidate | Baseline → candidate median, seconds | Decision |
| --- | ---: | --- |
| Cache Gaussian kernels without stream guards | 1.8902 → 1.8443 | Not safe to promote as-is |
| Kernel cache with stream/capture guards | 1.8440 → 1.8302 | <1% gain; added cache complexity not justified |
| Pair both final inverse solves | 1.8347 → 1.8615 | Slower; diagnostic allocated VRAM rises about 10% |
| Pair candidate Jacobian checks | 1.8462 → 1.8481 | No gain |
| Cache fixed support-size arithmetic | 1.8505 → 1.8481 | No meaningful gain |
| CUDA convolution for local-NCC sums | 1.9144 → 1.8758 | Overlapping/reversing timings; numerical trajectory changes |
| Reuse inverse buffers without autograd | 1.8833 → 1.8612 | Overlapping timings; no whole-call peak-memory reduction |

The exact-work candidates preserve bitwise registered images, masks, forward and
inverse maps, objectives, statuses and update counts on the planar workload.
Their truth RMS stays 0.2651503193. The convolution arm passes the truth gate but
changes a displacement component by up to 0.0139 mm. Its small, unstable timing
difference does not justify changing the numerical trajectory. CPU/CUDA and
batch agreement would require fresh qualification; passing the truth gate alone
is not numerical equivalence. No threshold was relaxed.
